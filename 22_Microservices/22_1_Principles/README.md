## Задача 1: API Gateway

### Сравнительная таблица решений

| Решение          | Маршрутизация | Аутентификация | Терминация HTTPS | Примечание |
| :---             | :---          | :---           | :---             | :---       |
| **Kong**         | Да            | Да             | Да               | Огромная экосистема плагинов, требует БД (PostgreSQL). |
| **Traefik**      | Да            | Да             | Да               | Идеален для Kubernetes, минимальная конфигурация. |
| **Apache APISIX**| Да            | Да             | Да               | Высокая производительность, требует etcd. |
| **Tyk**          | Да            | Да             | Да               | Полноценный API-менеджмент с графическим интерфейсом. |
| **KrakenD**      | Да            | Да             | Да               | Статeless, очень быстрый, но конфиг меняется только перезапуском. |

**Обоснование:**
Kong удовлетворяет всем требованиям
1. Обеспечивает маршрутизацию на основе конфигурации, поддерживает проверку аутентификации (JWT, OAuth2, Key-Auth) и легко настраивается для терминации HTTPS.
2. Это одно из самых популярных решений с огромным количеством готовых плагинов, что позволяет расширять функциональность без разработки.
3. В отличие от stateless-решений (KrakenD), Kong позволяет динамически обновлять конфигурацию через Admin API, что критично для крупной компании.
4. Kong отлично работает как в виртуальных машинах, так и в Kubernetes, в отличие от Traefik, который заточен именно под K8s.

Я бы предпочёл выбрать **Apache Kafka**, так как этот продукт обеспечивает выполнение требований задания, за исключением, в какой-то мере, простоты эксплуатации, где его, вероятнее всего, обходит **RabbitMQ**, но в остальном имеются преимущества.
